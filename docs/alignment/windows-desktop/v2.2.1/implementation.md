**D4 保持声明（非增量）**：`ask()` 仍 `ctx.layout.open(`${ctx.id}:${id}`, session, { tab: "select" })`——上游 select 语义为「保留窄屏当前视图」（宿主 `open()` 的 `select` placement 走 append+focus+reveal，**不触发**窄屏 `selectMobile` 分支）。即移动上 /btw 提问后不自动跳转 face，用户从 More 抽屉进入（face 显示最近 chat=刚问那条）。改走默认 `open` placement 会踩宿主窄屏分支的 transient 存储语义（`transient` 集按 tab 级字段计算，btw 的 tab 不带该字段，可能把 transient tab 持久入 strip）——风险大于收益，自动跳转留独立后续 Issue（先钉宿主语义）。

**上游既有存储效应（m-1 登记，说全不补）**：窄屏 select 分支的 `layout.panel.append` **不受窄屏守卫约束**——ask 在窄屏照常落 store；**窄屏期间积累的问答在视口加宽后以 strip tabs 重现（恢复 close 通道）**。同时窄屏 face 本身无 tab close 通道 ⇒ chat 在窄屏只增不删（删除仅桌面 strip close → `btw.remove`；换会话不清理）。这是上游「kept until its tab closes」语义在窄屏的结构性缺口，v1 **登记不补**（face 加删除/历史 UI 超出「入口适配」边界）。**生命周期边界**：in-flight 提问在用户离开会话后继续落入 store（model.ts onCleanup 注释逐字），仅 reload/桌面关闭该 tab/插件 dispose 放弃并保持 retryable——M-038 不触碰该语义；`session.generate` 有 AbortController，仅本地放弃重试，**远端不因客户端断开停止**的红线不受影响。
