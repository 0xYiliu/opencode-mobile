## G36 / G37 初始连接屏与 inline SSH 门禁

G36（issue #55）的 Settings 例外与跳转入口由 connection-inline-ssh 撤销；其历史交付事实由 connection-initial-ssh-entry/connection-method-layout/connection-label-nowrap vendor 记录保留。当前连接屏在同一屏内切换 Pairing、服务地址/密码、SSH 三种模式。SSH 直接呈现现有主机表单，不增加 route；Pairing/地址/密码草稿在模式切换时保留，SSH 草稿在连接屏存活期间以隐藏但挂载的表单保留。AppShell 在主机发布前取得初始屏所有权，只允许指定代次的指定主机在 SSH tunnel 建立且 `/api/info` 返回健康、认证成功后交接；401/403 表示服务可达但要求服务认证，不交接、不拆 tunnel。

### G37 验收与失败路径（issue #58）

- Pairing、密码与 SSH 三项可在同一连接屏切换；SSH 不创建新 route。直接地址连接成功后仍由原 upstream registry 接管；SSH 连接失败时保存记录保留，模式切走/切回可恢复与重试。
- 名称、target、service port 与凭据输入均先做本地验证；无效数据不触发 vault 写。新密码/私钥用新引用暂存，旧引用不覆盖；bound private key 替换密码按 UI 指示先取消勾选再重新勾选 Remember，保存创建新密码条目，旧密文留在 CredentialManager orphan 区，只有用户明确删除才清理。
- unknown key 走以 host ID + exact target/service port/fingerprint 为 keyed identity 的 HostKeyPrompt 明示信任/拒绝；prompt 同屏展示 host name、完整 target、SSH port、remote service port 与完整可选择/换行 fingerprint。主机记录变更会同步取消 pending confirmation/open；确认入参再次与待确认 target/port/fingerprint 比对，并在异步阶段和 transport.open 前验证记录未变。changed key 严格失败，需两步危险确认后 forget，再由用户显式重试。认证、bridge、unreachable、service-unreachable、incompatible 均显示可操作恢复路径。
- SSH health 的 401/403 在 InitialSshSetup 与 Settings → Server host-manager 共用与 SSH 身份分离的服务认证提示、「Check again」和本地 disconnect；认证密码只在 password input/component 与 runtime check 的短暂内存中，显式认证成功后只存 runtime 的 session map/upstream endpoint 内存字段，供 SSE `transport.update` 与 tunnel reconnect health 重检/endpoint rotation 继续使用，并以 UTF-8 Basic 编码。reconnect await 完成后再核对 AbortSignal、host generation/完整记录、ready state、exact endpoint 与 active attempt；已经 disconnect/edit/delete/reconnect 的迟到结果拒绝返回 URL/密码。401/403 明确拒绝旧密码时移除该会话值，要求重新认证；显式 disconnect、host edit/delete 也清除它。不绕过 HTTP auth、不关闭 tunnel 自动伪装 ready、不写持久层/日志。disconnect 只撤销设备侧 tunnel，不发远端 stop/interrupt。
- 所有异步手交回调带 owner generation 与 exact host ID 校验；handoff 还要求 SSH mode 当前 active、host ready 且 service authenticated。切回 Pairing/password、断开、替换 owner 后的迟到回调不得连接/交接错误 screen。模式切换保留 SSH 表单 draft。
- no-server / signed-out 的 Settings 特例不再存在；签出 HTTP URL 仍通过 `ConnectServerScreen url={signedOut()?.http.url}` 恢复。
- 冒烟清单：窄屏三模式来回切换并检查草稿；有效 SSH 首连通过 unknown key 显式确认后进入 shell；分别拒绝 unknown key、模拟 changed key、SSH auth failure、service 401/403、不可达/不兼容，验证对应提示、重试/编辑/本地断开；切回直连验证 signed-out URL；替换凭据后检查 orphan 元数据且无旧条目被静默删除。
- APK provenance/SW cache mismatch 已定位并修复：最初 MatePad 安装包不是当时源码构建，且旧 Workbox worker (`skipWaiting=false`) 控制 WebView、当前 worker waiting，导致旧 chunk 仍可见。Android shell 现在只在当前 origin 上 promote 等待 worker，并在 activation 后 reload；更新不清 app data/localStorage/vault。经最新 `install -r` 后 WebView active worker 为 packaged build、waiting 为空；实际点击 SSH 模式按钮显示 inline `Add SSH host` 表单且 URL 不变。Pairing↔SSH 模式往返以非机密 `example.invalid` 草稿验证保留并清空、未提交或保存。G37 inline entry/form render **PASS**（未提交真实凭据）；host-key 信任、真实 SSH auth、服务 401/403 与远端任务存活 E2E 仍 BLOCKED，需用户授权的远端主机/服务。

## 交互基线

- 交互主要由上游 app（vendored 静态构建）承载；issue #58 的 first-party InitialSshSetup 是连接屏内的共享 SSH 配置/恢复单元，调用 MobileHostManager/HostDialog/HostKeyPrompt 的现有能力。控件可用性不因构建通过而预声称。
- 壳层自有交互仅四项（均已实现、未验证，见 [units/shell-startup.md](units/shell-startup.md)）：返回键（`canGoBack` → goBack，否则结束 Activity）、SSL 错误处理（恒 CANCEL）、控制台日志（固定 tag，不含 URL 参数/请求头/凭据）、生命周期停止范围（仅本地回环 asset server）。issue #71 增第五项：相机权限授权链（`WebChromeClient.onPermissionRequest` 运行时授权——`CameraGrantPolicy` origin+资源白名单、三态呈现与纪律见 [units/connection.md](units/connection.md) 配对专节⑦-2）。
- 软键盘与视口：沿用上游 `viewport`（`interactive-widget=resizes-content`、`viewport-fit=cover`），见 [visual.md](visual.md)。**壳内软键盘行为的兑现者=原生 windowSoftInputMode（issue #75 勘误）**：`interactive-widget` 是 Chrome 浏览器层 viewport 特性，Android WebView 不消费——G31③ 实测判据按原生 resize/pan 实态判（layout viewport 是否收缩），非 meta 段。
- 深链：不实现（未注册 VIEW intent-filter，代码留 TODO）。评估完成（issue #71 验收 2，2026-10-30）；已确认不实施（决策 0007，2026-10-31）：HTTPS App Links 对用户自管服务器域结构性不可适用、自定义 scheme 不实施——三案对比、信任模型与激活条件见[决策记录 0007](../decisions/0007-pairing-deep-link.md)；粘贴/扫码（扫码已接入，[units/connection.md](units/connection.md) 配对专节⑦-2）承载导入。
- 返回手势：壳按 `onBackPressed` 实现，manifest 显式声明 `android:enableOnBackInvokedCallback="false"`——Android 16 起 targetSdk ≥ 36 的应用默认启用 predictive back，`onBackPressed` 将不再被调用，必须显式禁用才能维持该行为；迁移平台 `OnBackInvokedCallback` 需 minSdk 守卫（API 33+），为后续 issue 事项。与计划中 onBackPressedDispatcher 表述的差异已记录（见 [docs/build-and-verify.md](../build-and-verify.md) 偏差表）。
- 返回键实态（issue #20 落字、issue #75 勘误，[interaction-quality.md](interaction-quality.md) §一）：**依赖侧路由写入在册**——`@solidjs/router`（bun.lock pin 1.0.0）默认 History 集成对非 replace 导航调 `window.history.pushState(state, "", value)` 并 `saveCurrentDepth()` 写 `_depth`、监听 `popstate`（首方四包 src 零 History API 写入事实不变——扫描域自文档化局限）。**实测（issue #75 模拟器轮，AOSP WebView 113/API 34）**：依赖侧写入的同文档历史项不入 WebView `canGoBack()` 门——常规使用中返回键实际语义=结束 Activity（整页项堆叠后同然；复现 ×2）；脚本 `history.back()` 可达 `popstate`（SPA 内部回退不受影响，路径回退零重载）；整页导航项（同窗导航类+通知路由 `loadUrl` 同类机制实测）入 `canGoBack()` 门——返回键=回退 WebView 历史（整页回退）。例外为一**类**而非单点——发生任何 WebView 整页导航之后（已知形态：OAuth 授权 `window.open`（G25③ 实态判定）、webfetch/exa 工具链接 `target="_blank"`（壳内无 setSupportMultipleWindows，同为同窗导航）、消息内 http 链接（G28⑦ 同源复测）、通知 tap 路由 `loadUrl`（#75 枚举增补，真机 tap 复验待轮））。hwschromium（MatePad）对同文档项的 canGoBack 处理=复验点在册。in-app 后退（对话框/dock/抽屉关闭）不经返回键；可接受性判定与 back 集成候选归 G31②（移动适配候选池）。#76 边界：`openExternal`（ACTION_VIEW）不进 WebView 历史、与例外类正交。

## 失败路径处置协议

任一门禁运行失败时，按以下顺序处置，不得跳步：

1. **复现失败报告**：可复现步骤、设备/API/WebView 版本、脱敏日志（不含凭据、不含 URL 查询参数）。
2. **影响范围**：明确失败影响哪些单元与验收项，哪些不受影响。
3. **备选方案**：列出可行替代（如 G3 的预案 A/B/C），含各自代价与安全影响；备选不得默认「原生重写」或「关闭浏览器/传输安全」。
4. **用户决策**：由用户选定处置后再继续产品化工作；未获决策前该路径停在那里并如实标注。

## 凭据 notice（修订：可选记住，issue #4）

凭据基线为 memory-only（connection-password-memory-only）；issue #4 起提供**可选**的安全记住（vault 加密落盘），用户须知晓并接受以下行为：

- **不勾选「记住」时，刷新或重启 App 后需重新输入服务密码**：密码只存在于内存，不写入任何持久化后端（localStorage、桌面存储、草稿存储均收不到）。
- **勾选「记住」时**（vault available，issue #4）：密码经 Android Keystore 加密落盘（信封 v1，无明文形态），重启后由 connection-credential-hydration hydration 自动恢复到内存；勾选框仅在 vault available 时可用，unavailable 时禁用+说明（显式状态，无明文回退）。
- **配对重连需重新认证**：连接中断后重连不能复用已落盘的凭据（memory-only 语义未被 vault 改变）。
- **credentialRef 不是凭据（issue #3 扩展）**：主机记录与连接记录中的 `credentialRef` 是指向凭据条目的非机密引用标识符，随记录持久化；它**不携带任何凭据值**。引用的目标现在真实存在（vault 条目），解析经 vault-backed resolver 仅入内存。
- **失效与恢复**（issue #4）：vault unavailable（握手未 ack/非 Android）→ 记住功能禁用+横幅；条目 corrupt/unsupported → 该条目按失效矩阵标红，重输后重存（in-place，ref 稳定）或删除；TEE 重置等 Keystore 失效 → 横幅+重输或一键清除。恢复=丢失+重输，合法且显式；无额外解锁（不设生物识别/锁屏门，设计免除：设备锁定时 App 本不可用）。
- **vault mutation outcome unknown**（protocol v2）：put/remove 已派发后若超时、页面销毁/导航、响应畸形或部分 I/O 失败，UI 不自动重试、不自动删除/回滚；native 写请求携带随机非秘密 candidate id，put 先更新无值索引再写密文，未知结果返回该 candidate reference。host/server 仅在已确认 put 成功后切换旧 `credentialRef`；direct/SSH caller 保持原引用或不提交配置。提示用户检查该引用，但明确条目可能尚未显示（例如索引写入未成功），不声称完整可恢复或原子性。remove 检查实际删除结果并保留索引行，尽可能允许用户重试显式删除。这个机制不提供跨文件事务或断电 durability。
- 上游界面不自带 memory-only 提示；「记住」勾选框的禁用说明（connection-remember-credential i18n）与凭据管理器横幅（mobile-hosts i18n）是 App 内提示口径，本 notice 为文档口径。

该 notice 的真机核验（localStorage 负例、重启后行为、vault 落盘形态）归 G9/G11 与 C1–C4。

## 主机管理交互（已实现（未验证）：issue #3；设备核验 BLOCKED，归 G13–G15）

- **host-manager（设置 → servers 标签页）**：SSH 主机列表（名称/target/状态徽标），行内动作：编辑（→ host-dialog）、删除、连接/重连；空态引导新增。删除为本地操作——**零远程调用**，远程服务/任务不受影响（红线，测试断言）；删除活跃主机不弹「停止远程」类操作。
- **host-dialog（SSH 主机新增/编辑）**：字段 name（唯一校验，重名行内报错不写入）、target（格式校验 `[user@]host[:port]`）；凭据绑定块（issue #4 重构，见上）；保存前校验失败保留表单；**保存/健康检查失败保留原配置**（不写入注册表）。取消/关闭不产生任何变更。
- **取消切换语义**：连接发起后取消（connect 过程、host-key 确认、重连过程）恢复进入前的来源态（idle 或 offline），无残留副作用（状态机 T13，测试锁定）。
- **host-key-prompt（stub）**：状态机进入 hostKeyUnverified 时展示指纹确认；当前 stub 恒拒绝——确认 UI 组件已立桩但**挂载点未建**（无任何界面渲染它），在本构建不可达（真实校验与挂载归 #6，BLOCKED）；**不存在"跳过校验"选项**。
- **host-key 三态交互与变更恢复（issue #6，已实现（未验证））**：①**未知**（首次连接）——HostKeyPrompt 行内挂载于 host-manager，展示 `SHA256:…` 指纹，仅「信任并连接」/「拒绝」两动作（确认先于任何认证材料发出）；②**已知**——store 命中即 trust，无弹窗；③**变更**——硬失败 `host-key-changed`，**永不自动覆盖**；恢复入口=行内危险按钮（红色警示，明示主机密钥已变化、可能中间人），一次显式危险确认后 `removeHostKey` → 下次连接回未知确认流。三态 UI 与挂载随 #6 实现交付，真机核验归 G14/G17。
- **服务端口（issue #6，已实现（未验证））**：host-dialog 增 servicePort 输入位（默认 4096）并与 target 内 SSH 端口双标签去混淆（「SSH 端口」vs「服务端口（远端 OpenCode 服务）」，见 [units/server-list.md](units/server-list.md)）。
- **凭据绑定与凭据管理器（已实现（未验证）：issue #4）**：
  - host-dialog 凭据绑定块取代 #3 的自由文本 ref 输入：表单不再存在任何凭据值/引用标识输入位；SSH 主机行内显示已绑定指示，凭据管理器入口在 host-manager 头部。
  - 直连服务的「记住」勾选随上游连接对话框（connection-remember-credential，真值表见 [units/connection.md](units/connection.md)）；**healthPreview 附注**：连接前健康预览（输入过程中的探测）不解析凭据引用、不读 vault——预览只验证地址可达性，权威的凭据检查发生在保存时。
  - 凭据管理器：仅元数据（kind/label/时间，无值）；unavailable 横幅、corrupt/recovery-needed 标红与恢复动作（重输/一键清除）；孤儿区（无宿主引用的条目）列出对账并可删除。
  - **credentialRef 透传现状（issue #166 已修复）**：dialog+password、dialog+link/QR、以及 screen 在 vault 可用且密码非空时均保留并写回 ref；旧的「dialog 限 password / screen 整体覆盖丢 ref」仅属于 #148 历史 finding。当前唯一已知边缘是地址栏粘贴配对链接的 prior URL 原文查找可能落空；该边缘不清理 vault、不造成安全泄漏，重配对自愈路径仍可达。

- **断开语义**：ready 态的「断开」走状态机 T13（cancel）：恢复来源态 idle、清空内存端点，零 transport 调用；「删除」走 T14：仅删本地记录，零 transport 调用。两者均不向远程发出任何信号（红线，单测断言）。
