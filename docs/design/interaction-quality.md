本文是「移动交互质量」横切关注点的**索引与收口层**（issue #20）：窗口与进程形态、导航与切换保持、键盘/IME/焦点、viewport/旋转/响应式、读屏/对比度/触摸目标盘点、偏好恢复与 Desktop actions 平台映射。**authority 边界声明**：本文是索引与收口层，不重定义任何单元契约——各交互契约的权威表述仍在对应单元文档与 G 门禁（各节标注），冲突时以单元文档为准并按双向变更协议回修本文。静态结构锚由 `scripts/verify-interaction-quality.ts` 锁定（与既有探针分工：只锁既有探针未覆盖之锚；交叉引用复核性断言显式标注，见各节「探针」行）。运行期行为归 **G31** 移动交互质量 walkthrough 门禁（[interaction.md](interaction.md)），G31 未过前本文全部运行期表述只声称「已实现（未验证）」（第十七处落字）。

## 一、窗口与进程形态

- **单窗口壳**：`android/app/src/main/java/ai/opencode/mobile/MainActivity.kt`——单 Activity 单 WebView（`onCreate` 内创建 WebView 并 `setContentView(webView)`）；`AndroidManifest.xml` 唯一 LAUNCHER activity（无 `launchMode`/无 `configChanges`/无 `screenOrientation`）；deep link 未注册 VIEW intent-filter（MainActivity 头注 TODO 在册，[units/shell-startup.md](units/shell-startup.md) 权威；外链唤起已确认不实施——[决策 0007](../decisions/0007-pairing-deep-link.md)，2026-10-31）；权限三元组 `INTERNET`+`POST_NOTIFICATIONS`+`CAMERA`（本句原为「唯一权限 `INTERNET`」的历史快照——issue #23 增 POST_NOTIFICATIONS、issue #71 增 CAMERA；CAMERA 为运行时权限且仅经 WebView `onPermissionRequest` 应用内授予，`CameraGrantPolicy` origin+资源白名单见 [units/connection.md](units/connection.md) 配对专节⑦-2）。**无多窗口结构面**：壳内无 `onCreateWindow`/无 `setSupportMultipleWindows`——`window.open` 与 `target="_blank"` 链接在壳内均为**同窗导航**（G25③ 在册实态判定、G28⑦ 同源口径），不产生第二窗口。
- **返回键当前实现（#186）**：壳仍由 `onBackPressed` 接收系统返回，但在 WebView 已初始化且当前 URL 通过 packaged loopback app-origin gate 后，先向 main frame 发固定 `{version:1,type:"back",requestId}` 请求，调用 `window.opencodeMobileBack.consume(request)`；`requestId` 为不透明值，UTF-8 ≤256 bytes，request 不含 URL/token/credential。native 仅保留一个 pending dispatch，500ms 超时、整页导航、Activity destroy、stale/duplicate/malformed/wrong-origin/wrong-type/oversize 均 fail-closed；只有 bare JSON `true` 视为消费。其余结果沿原 `webView.canGoBack()`→`webView.goBack()`→`super.onBackPressed()` fallback，非 app-origin 页面完全不进入 binding。manifest 显式 `android:enableOnBackInvokedCallback="false"`（Android 16 起 targetSdk ≥ 36 默认启用 predictive back，不禁用则该回调成为死代码）；迁移平台 `OnBackInvokedCallback` 需 minSdk（API 33+）守卫，为后续 issue 事项（[interaction.md](interaction.md) 交互基线在册）。
- **上游 SPA 首方零 History API 写入（依赖侧写入在册，issue #75 勘误）**：上游四包 src 全域**浏览器 History API 的写入/监听调用形态**零命中（扫描域=四包 src 树，为自文档化局限——依赖侧写入不在其内；titlebar 的 `history.back` 是应用内 history controller 方法，不是浏览器 History API）；唯一首方 History API 触点为 `app/src/runtime/platform/pwa.ts` 的 `history.replaceState(history.state, "", url.pathname + url.search + url.hash)`（PWA URL 清理，replaceState 不新增历史项）。**依赖侧历史写入者（issue #75 实证）**：`@solidjs/router`（bun.lock pin 1.0.0）默认浏览器 History 集成——非 replace 导航调 `window.history.pushState(state, "", value)` 随后 `saveCurrentDepth()` 写 `_depth`（replace 导航走 `replaceState`），并监听 `popstate`（pin 包 dist 与构建产物 `index-CYqCdjPV.js` 双双在册核验）；移动 entry（`entry.tsx` render）不传 `router` prop → `app.tsx` 的 `props.router ?? Router` 落默认 Router。tab 切换/会话打开/设置首开等常规导航走默认 push。故「SPA 零 History API 写入」仅在首方扫描域成立，常规使用中 WebView history 存在依赖侧写入的同文档项——但其不入壳层 `canGoBack()` 门（下条实测）。
- **返回键历史/同窗导航边界（issue #75/#186）**：依赖侧 `@solidjs/router` 的 `pushState`/`popstate` 事实与 AOSP WebView 113/API 34 的历史语义仍作为历史证据保留：同文档项不一定进入 `canGoBack()`，整页同窗导航项可以进入。#186 不把 `canGoBack()` 当作 SPA 路由栈，而是让 app-side `goBack` layer（order 90）先处理 titlebar history；只有 chain decline 后才执行原 WebView history fallback。OAuth、工具输出/消息内链接、通知 `loadUrl` 等整页导航仍属于 fallback 的同窗导航类；`openExternal`（ACTION_VIEW）不进入 WebView 历史。硬件返回、WebView 历史与 app-side chain 的贯通运行期结果本轮未复测，归 G31 / #186 **BLOCKED / NOT RUN**。
- **旋转=Activity 重建**：manifest activity 零 `configChanges` 声明——旋转、深浅色切换、键盘可用性变更与尺寸变更（含分屏拖拽）均触发 **Activity 重建**：WebView 销毁重建、回环 asset server 重启、五桥经 `onPageFinished` 重新握手、页面完整重载；恢复走 web 层持久化链（persist flush：`visibilitychange`→hidden 与 `pagehide` 强制落盘，[recovery.md](recovery.md) 场景②③）。这是**结构实态而非缺口**；壳层实例状态恢复未实现（`onSaveInstanceState` TODO，[units/shell-startup.md](units/shell-startup.md) 权威，`verify-recovery.ts` 组 4 已锁）——返回键退出即进程终止场景的恢复链由 [recovery.md](recovery.md) 冷启动八环承接。相关核对项已预登记：G9（生命周期）、G29⑤（Office 旋转重排）、G24⑥（旋转后重连的终端陈旧尺寸）、#16 L9（SAF 保存中途旋转）。
- 探针：组 1（壳层返回键三锚+manifest 结构+`configChanges` 零命中负断言）与组 2（首方 src `pushState`/`popstate` 零命中哨兵（扫描域=四包 src，依赖侧写入自文档化域外）+`replaceState` 唯一首方触点+`target="_blank"` 两锚）。

## 三、键盘、IME 与焦点

- **viewport 基线**：`app/index.html` meta viewport content 逐字 `width=device-width, initial-scale=1, interactive-widget=resizes-content, viewport-fit=cover`——**壳内软键盘行为的兑现者=原生 windowSoftInputMode（issue #75 勘误）**：`interactive-widget` 是 Chrome 浏览器层 viewport 特性，Android WebView 不消费它（meta 段在壳内接近 inert，浏览器/PWA 语境才生效）；壳 Manifest 未声明 `windowSoftInputMode`（默认 `adjustUnspecified`，系统按内容可滚动性在 resize/pan 间裁定）——模拟器实测（API 34）键盘弹出时 layout viewport 收缩（`innerHeight` 782→507、`visualViewport.offsetTop` 恒 0、layout 与 visual 同值）=裁定 resize、聚焦输入全程可见零遮挡（MatePad hwschromium 同判据复验点在册）；`theme-color` meta 由主题系统运行期更新。
- **KeyboardInsets（上游软键盘 safe-area 联动机制）**：`app/src/runtime/platform/keyboard.ts`——`window.visualViewport` resize + `window` resize + `document` focusin + focusout **四监听**；editing 判定（`active.isContentEditable` 或非只读 input/textarea）；keyboard 判定（`editing && root.clientHeight - viewport.height * viewport.scale > 100`）；键盘弹出 → `root.style.setProperty("--safe-area-inset-bottom", "0px")`、收起 → `removeProperty`。挂载：`entry.tsx` import + `<KeyboardInsets />`。issue #75 模拟器实测（resize 形态）：键盘弹出时 `clientHeight` 与 `visualViewport.height*scale` 同步收缩、差值 0 → `>100` 判 False → 置零 no-op（结构性无双避让，机制自文档化无害）。#186 的 mobile drawer/titlebar 继续消费 `env(safe-area-inset-*)` 与 `--safe-area-inset-bottom`；本轮没有增加 native `WindowInsets`/edge-to-edge 处理，safe-area 设备实态仍未验证。
- **终端面**（[units/terminal.md](units/terminal.md) 权威，引用不重定义）：`runtime/extension/panels.tsx` 三处 `window.visualViewport` 高度同步（dock viewport store → `scheduleFit`；**高度同步锚首锁在 `verify-terminal.ts` 组 6，本文探针标交叉引用复核性断言**）；ghostty-web 隐藏 `textarea` 承载输入与原生 IME 合成；ResizeHandle 移动分支 `md:hidden`；**六缺口在册**（软键盘 fit/滚动锚定、CJK IME 组串、外接键位透传、触屏选择/复制/粘贴、控制键软输入、读屏焦点——G24⑦⑧⑨ 权威）。
- **composer 面**：`composer/submit.ts` 逐字 `if (window.matchMedia("(max-width: 767px)").matches) input.editor()?.blur()`——窄屏提交后 blur 收起软键盘（**`verify-session-workbench.ts` 已首锁，本文探针标交叉引用**）。
- **focus 安全语义**（#10 在册）：`DockPrompt` 无内建按键语义、permission dock 不传 onKeyDown、请求面零 `autoFocus`——无键盘时**无默认审批**；question dock 完整 `role="radio"/"checkbox"`/`aria-checked`/`aria-keyshortcuts`/数字键直选/方向键/Esc=reject（[units/permission-requests.md](units/permission-requests.md) 权威）。
- **外接键盘键位面**：`shell/commands/command.tsx` 全局 keydown keymap；`DEFAULT_PALETTE_KEYBIND = "mod+k,mod+shift+p"`；session.new `mod+shift+s`、session.background `ctrl+b`、file.open `mod+p`、tab.prev/next（hidden）；`settings.v3.keybinds` record 可覆盖；终端 `terminal.toggle/new/close` keybind（G24⑧ 权威）。**软键盘无法产生 mod 类组合——全局键位命令依赖物理键盘是实态**（§七映射清单的核心标注；G31⑤ 判定）。
- 探针：组 3（viewport meta 四段+theme-color+keyboard.ts 四监听+safe-area 对+`> 100` 判定+entry 挂载+panels visualViewport 三锚——其中高度同步锚为交叉引用）。
